## Ranked findings

### 1. Fix style equality once, in one place

**P1 correctness and duplication.** `Goo/Tree/Reconciler.gs:1403-1408` and `Goo/Style/Resolver.gs:649-654` implement separate payload comparison chains. Only Resolver compares ShaderEffect identity. An effect-only update can therefore be dropped before Resolver sees it.

A native proof used a real SDL click. Cell state selected the terminal effect, but the mounted node still referenced the liquid effect. The current glass demo itself switches correctly because its BorderRadius also changes, forcing the whole style list to update. Earlier mode-state QA did not cover this isolated replacement case.

Use one internal comparator for both sites and retain each payload's existing value or identity semantics. Add an effect-only mounted-node/render regression. Once correctness is covered, an identical-payload fast path can skip unrelated casts and comparator calls for common numeric entries. That CPU benefit is unmeasured. This needs no public API break.

### 2. Repair the five stale hit-test fixtures

**P1 verification.** `Goo/Input/HitPolicy.gs:3-31` intentionally excludes inert content from self-hit testing. The failed tests still assume inert Container/Shape nodes are input targets:

- `tests/Goo.CoreBehaviorTests/Accessibility/AccessibilityFixtures.gs:936-943`
- `tests/Goo.CoreBehaviorTests/Input/ClipPathInputFixtures.gs:114-177`
- `tests/Goo.CoreBehaviorTests/Input/CoreInputFixtures.gs:59-68`, `1603-1647`, and `2237-2256`

A temporary candidate made the asserted Containers explicitly hittable and gave the asserted Shape an input handler. All five previously failing tests passed, with unchanged production source and an unchanged checkout. The accessibility failure occurred before allocation measurement, so it does not establish an allocation regression. Apply those fixture changes, then run the complete core suite.

### 3. Remove four unreachable readback cleanup branches

**P2 small cleanup.** `Goo/Rendering/Vulkan/VulkanWindowTarget.Readback.gs:142` initializes local `reusedSlot` to false. Its first possible true assignment is after acquisition at `195-197`. Four cleanup branches at `152-154`, `159-161`, `168-173`, and `178-180` precede acquisition and cannot execute.

Remove those branches and keep the post-acquisition ownership handling intact. This is a clarity improvement with negligible expected frame-time effect. Validate readback, failed-idle recovery, and close behavior.

### 4. Consolidate exact frame-failure finalization copies

**P2 organization, moderate implementation risk.** `Goo/Rendering/Vulkan/VulkanWindowTarget.Core.gs:896-901`, `985-990`, `1011-1016`, and `1047-1052` repeat the same diagnostic/active-frame finalization. Related error paths differ in abort order, retry behavior, and exception handling.

Extract only the identical finalization step first. Keep differing resource and recovery decisions explicit at their call sites. Later, consider one owner for readback acquisition and teardown instead of parallel request/pool/target/lease flags. A broad Vulkan lifecycle rewrite is not an easy win. Preserve queue-wake, queue-isolation, failed-idle, device-loss, and resource-lifetime gates.

### 5. Consider folding the keyed-order prepass into reconciliation

**P3 unmeasured CPU candidate.** `Goo/Tree/Reconciler.gs:1092-1117` calls `childOrderChanged` at `1431-1445`, then traverses the incoming list again. Comparing order while the main loop already visits each child can remove one loop/traversal. The key comparisons themselves still remain.

Only pursue this if stable/reordered keyed-parent measurements show a useful reduction. Preserve replacement, handle movement, rollback, and structure invalidation. No allocation saving is claimed.

## API decisions

The reviewed APIs do not justify a broad breaking redesign. Keep ShaderEffect setter change-result booleans, ShaderEffectData size/version/disposal observations, and the explicit seeded-mount lifecycle unless a concrete capability or maintenance problem emerges. Fewer methods alone is not a sufficient reason to break them. Likewise, collapsing Cell.Animate overloads would change explicit-null behavior without a demonstrated caller or implementation benefit.

`Window.Transparent` at `Goo/Window/Window.gs:186-193` is worth a small lifecycle decision: it is documented as affecting the next open, unlike live window properties. Either keep and clearly group creation settings, reject changes while open, or make it construction-only. This is API clarity, not an undocumented rendering failure. Choose the smallest rule that makes the lifecycle obvious.

## Defer

- Incremental path-registry sweeping. `VulkanPathIdentityRegistry.gs:57-80` does a full sweep before lookup, but changing maintenance affects dead-record retention and Count semantics. Measure large distinct-path churn before changing it.
- Allocation/binding unification, global/device proc-loader helpers, and generalized frame-slot traversal. They need stronger benefit evidence than line reduction.
- Direct upload and compare-before-write. Existing measurements already rejected them.
- Broad comment removal, file splitting by line count, and new helper/DSL layers. The reviewed core ownership boundaries are more useful targets.
- The duplicated DeviceLost check is not called dead code here without a separate concurrency/confinement proof.
