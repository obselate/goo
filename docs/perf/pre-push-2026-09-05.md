# Pre-push benchmark decision, 2026-09-05

**Retain staged primitive upload. Reject and remove the direct-upload experiment.**
Direct mode increased median frame cost by roughly 14 to 19 times on the tested RTX
3080. The retained pipeline-identity and shared-timeline changes remain accepted for
capacity, native-object reduction, and completion lifetime. Their combined frame
measurements do not establish a general speed improvement. Physical-Mac qualification
is deferred because no physical Mac is available. No commit or push was performed.

## Environment and measurement scope

Linux 7.2.0-1-cachyos, NVIDIA GeForce RTX 3080, driver 610.57.04, .NET 10.0 with SDK
10.0.302, Gsharp.NET.Sdk 0.4.1. A dedicated KWin virtual Wayland compositor used a
1600 by 1000 output at scale 1. Workload windows had VSync disabled. Timing runs had
Vulkan validation disabled and diagnostics enabled. Correctness runs used validation
separately. No compiler build or second benchmark ran during timing.

The normal desktop remained active, including s&box and screen-capture activity.
Per-run GPU temperature, clocks, utilization, power, and CPU load were recorded.
These are balanced comparisons under that desktop load, not isolated-machine results.
They support rejection of the repeated large direct-mode slowdown. Small timing
differences in the broader comparison remain workload and environment specific.

Frame measurements cover forced-frame host work through queue handling. They are not
physical input latency, GPU completion time, or an FPS claim. Tables report medians of
independent run-level statistics. Paired percentage changes are computed within each
pair and then summarized, so their signs can differ from a ratio of the two medians.

## Direct upload

Both lanes used the same frozen candidate Goo and harness binaries. Only the selected
upload mode differed. Every direct run reported actual `Direct` mode with no fallback.
Each process rendered 1,000 boxes, warmed for 300 frames, and measured 500 frames. Four
pairs alternated lane order for each of unchanged, sparse, and full updates, for 24
validated runs. Workload order also rotated.

| Workload | Staged P50 | Direct P50 | Staged P99 | Direct P99 |
| --- | ---: | ---: | ---: | ---: |
| Unchanged | 1.188 ms | 21.979 ms | 1.968 ms | 25.462 ms |
| Sparse | 1.304 ms | 22.199 ms | 2.318 ms | 25.587 ms |
| Full | 2.857 ms | 40.467 ms | 4.013 ms | 46.007 ms |

Direct was slower at P50, P95, and P99 in all 12 workload pairs. Managed allocation P50
and P99 remained 512,568 bytes per frame in both lanes. Direct removed primitive GPU
transfer bytes, copy commands, and transfer barriers. It still encoded all 128,000
record bytes per frame and retained the CPU comparison/history work. Zero primitive
copies does not mean zero GPU work for the frame.

An initial 300-warmup/200-sample unchanged calibration measured P50 1.240 ms staged and
22.466 ms direct. Before confirmation, the planned fine-tail study was shortened to
the four-pair 300/500 design above. The repeated large failure made the proposed
10,000-sample tail qualification unnecessary for rejection. No unrun long phase is
included in the results.

The selected direct allocation was host-coherent but not host-cached. Expensive host
access to that memory, including the encoder's rereads, is a plausible explanation.
This is an inference, not an isolated profile of the cause. No physical noncoherent
device or Mac performance claim follows from this result.

The exact archived direct-experiment patch was reversed after all 13 paths matched
their recorded candidate hashes. All 12 modified files then matched their pre-direct
hashes and the new direct-only smoke file was absent. The mode switch, direct-only
allocator helpers, test route, and CI route were removed. Earlier metrics, queue-wake,
pipeline, and timeline work were preserved. The old implementation and correctness
evidence remain documented in the [historical experiment](primitive-direct-upload.md).

## Retained pipeline and timeline changes

The comparison used frozen A, before pipeline byte identity, and frozen C, after the
timeline and layer-pool work but before direct upload. Each runtime used its matching
harness. Source and artifact checks establish identical common timed workload paths.
This compares the retained package, including timestamp migration and layer-pool LRU
reuse. It does not isolate the pipeline lookup or timeline semaphore change.

Six alternating-order pairs ran two workloads, with 300 warmup and 2,000 measured
frames per process, for 24 validated runs. The small shader-effect workload changes a
parameter each frame. The image-effects workload mounts 256 cards and changes eight
items per frame, exercising images, layers, and completion handling.

| Workload | A P50 | C P50 | A P99 | C P99 | Median paired P50 / P99 change |
| --- | ---: | ---: | ---: | ---: | ---: |
| Shader effect | 0.361 ms | 0.359 ms | 1.669 ms | 1.577 ms | +1.22% / -3.67% |
| Image effects | 6.210 ms | 6.168 ms | 9.279 ms | 9.300 ms | -1.44% / -0.77% |

Pair directions are mixed. Image-effects P99 improved in four of six pairs, and
shader-effect P99 improved in five of six. Shader P99.9 has a median paired increase
of 7.96% with mixed directions, but only about two tail samples per run. It does not
establish a precise extreme-tail effect. These runs show no consistent P50/P99
regression across the retained package, and do not support a general frame-speed claim.

Image-effects native object allocations fell in all six pairs, from a median 6,560
to 5,346 per 2,000 measured frames, an 18.51% reduction. Allocation churn remains in
this workload. Native device-memory allocation stayed zero. Managed allocation P50
remained 650,368 bytes per frame. The shader workload retained zero warm managed,
native-object, and device-memory allocations in both versions.

The first image-effects calibration exited successfully, but the runner incorrectly
required zero native object allocations from the historical baseline. That check was
changed to validate a nonnegative measured count. The calibration and runner failure
were preserved, and a fresh balanced series supplied the table above. No runtime
assertion was removed.

## Final verification

The restored Release framework passes all 12 API tests. AsyncReadbackSmoke and
FailedIdleSmoke Release builds pass with zero warnings and errors. The rebuilt async
Goo and harness binaries are byte-identical to frozen C, so the retained-package
benchmark measures the exact final tested implementation.

All 11 selected runtime lanes pass: primitive metrics, retention, readback, pipeline
identity, timeline completion, queue isolation, live pacing, recovery with present
fences, recovery with presentation maintenance disabled, and the lavapipe CI-wrapper
queue-wake and timeline gates. Both recovery paths report resolved stage timestamps
and zero remaining resources. The validation-enabled runs emit no Vulkan validation
errors. Strict G# lint passes with the existing CI GL0005/GL0006 exclusions, as do
scoped whitespace checks and CI YAML parsing.

This is the focused verification of the restored implementation, not a hosted CI run
or full platform qualification. The previously recorded, baseline-reproduced optional
offscreen-failure smoke issue remains outside this result. Physical-Mac testing remains
deferred.

## Evidence and reproduction

The [evidence directory](https://github.com/obselate/goo/tree/1003f46a94a9087b289326c52c7a6ee600766b7a/docs/perf/evidence/pre-push-2026-09-05) preserves runner scripts,

included as new binary artifacts in the repository.

Repeat the direct experiment only by rebuilding its archived candidate patch into an
isolated runtime directory. The current source has no direct-mode switch. Use the
archived short confirmation configuration with `run_benchmark.py --phases short`, then
`analyze_benchmark.py --decision-policy none`. The unused long-phase configuration
does not describe executed work. Use `run-broad.py` with the recorded A/C runtimes for
the retained-package comparison and `analyze-broad.py` for its six-pair analysis.
